# MD Genius AI Startup Launchpad

Web platform for the MD Genius 8-week AI startup accelerator: applications, cohorts,
curriculum, project roadmaps, mentor and investor sessions, and an AI Coach.
Available in English and Spanish (neutral Latin American).

## Stack

| Layer | Technology |
|---|---|
| Client | React 18, TypeScript, Vite, TanStack Query, Wouter, shadcn/ui, Tailwind, react-i18next |
| API | Express on Node 22, Drizzle ORM, express-session (sessions stored in Postgres) |
| Database | Postgres: Supabase in production, Docker locally |
| Files | Supabase Storage, private bucket `uploads`, signed URLs |
| Email | Resend (optional; links are logged without a key) |
| AI Coach | Claude via the Anthropic API (optional; the coach answers "not configured" without a key) |
| Hosting | Vercel: static client plus one serverless function for `/api/*` |

## Layout

```
api/index.ts          Vercel function entry (wraps the Express app)
server/app.ts         Express app factory: middleware, auth, routes, errors
server/index.ts       Local/self-hosted server (API + client on one port)
server/routes.ts      REST API
server/storage.ts     Database queries
server/auth.ts        Sessions, login state, isAuthenticated
server/fileStorage.ts Supabase Storage uploads and downloads
server/email.ts       Resend emails (password reset, invites) in English and Spanish
server/i18n/          Spanish for API messages (middleware + dictionary)
server/translations.ts Allowed translatable fields per content type, sanitizer
server/rateLimit.ts   Postgres-backed rate limiting for auth endpoints
shared/schema.ts      Drizzle schema, Zod validation schemas, shared types
migrations/           SQL migrations (drizzle-kit)
client/src/i18n/      i18n setup and EN/ES catalogs (locales/{en,es}/<area>.json)
client/src/components/brand/  Logo, NodeRule, ProgramTrack, ProgressRing, ConnectorBadge, …
client/public/brand/  Logo files (generated by scripts/brand/build-logos.mjs)
tests/                API tests (vitest + supertest, real Postgres) and catalog checks
docs/                 Product requirements, design, i18n style guide, project history
```

## Roles

`public_visitor` → `applicant` (after submitting an application) → `participant` (after
acceptance). `mentor`, `investor` and `administrator` are assigned by an admin.

## Design system

The UI follows the MDGeniusAI brand guideline. The plan and tokens are in
`docs/design/brand-redesign-plan.md`.

- Colors are tokens in `client/src/index.css` (HSL channels, so `bg-primary/10` works):
  Navy `#082B42`, Steel `#3A607D`, Mist `#97B7C1`, White Smoke `#F3F3F3`. Muted text is
  `#5F6B74` (Grey `#7F7F7F` fails AA contrast). The app is light-first.
- Fonts: Space Grotesk (`font-display`) for titles, UI and data; the Helvetica stack for
  body text and buttons.
- Controls follow the guideline's button samples: pill buttons (Steel→Navy primary,
  white→Mist secondary), 44px inputs, segmented pill tabs, 16px cards with soft shadows.
- Brand shapes are components in `client/src/components/brand`. `MistPanel` is for one
  highlight per page, `.hero-surface` / `.bg-brand-gradient` only for heroes and the
  auth panel, and status chips follow the rule: not started dashed, in progress Steel,
  done Navy.
- Icons are Lucide at stroke 1.5 (set globally).

## Languages (English and Spanish)

- Every interface string lives in `client/src/i18n/locales/{en,es}/<area>.json`, one
  catalog per area, used with `useTranslation("<area>")`. Keys are type-checked against
  the English catalog.
- The language is an account setting (`users.locale`, `PUT /api/auth/user/locale`) and
  an EN | ES switcher. Before sign-in the app uses the saved choice, then the browser
  language. Dates use `intlLocale()` (`es-419` / `en-US`); never pass `undefined`.
- Admin-entered content (cohorts, modules, lessons, quizzes, milestones, roadmap
  templates and items) stores Spanish in a `translations` jsonb column
  (`{ es: { title, … } }`). Show it with `useLocalized()` from `client/src/lib/localized.ts`,
  which falls back to English per field. Quiz answers stay on the base questions.
- Stored values (statuses, roles, stages, options) are never translated; display them
  through label maps keyed by the stored value.
- API messages are translated for Spanish users by `server/i18n`; emails and the AI
  Coach use the user's language.
- Spanish tone and glossary: `docs/i18n/spanish-style-guide.md` (tú, respectful and
  professional, no exclamation marks).
- Tests enforce it: `tests/i18n-catalogs.test.ts` (same keys and placeholders in both
  languages), `tests/i18n-hardcoded.test.ts` (no hard-coded screen text) and
  `tests/server-messages.test.ts` (every server message has Spanish).

## Local development

Requires Node 22 and Docker.

```bash
cp .env.example .env        # first time only; set SESSION_SECRET
npm install
npm run db:up               # Postgres 16 on localhost:5487
npm run db:migrate          # apply migrations
npm run dev:local           # http://localhost:5055
```

Register an account in the app, then make it an administrator:

```bash
docker compose exec -T db psql -U postgres -d launchpad \
  -c "update users set role='administrator' where email='you@example.com'"
```

Uploads, emails and the AI Coach need the optional keys in `.env.example`.

## Tests and checks

```bash
npm run check   # TypeScript
npm test        # API, email, AI Coach and translation tests (launchpad_test database, created automatically)
npm run build   # client + self-hosted server bundle
```

CI (`.github/workflows/ci.yml`) runs all three on every pull request.

## Database changes

1. Edit `shared/schema.ts`.
2. `npm run db:generate -- --name short_description` creates a SQL migration in `migrations/`.
3. `npm run db:migrate` applies it locally. Commit the migration with the schema change.
4. Apply it to production before deploying code that needs it:
   `DATABASE_URL="<session pooler URL>?sslmode=no-verify" npm run db:migrate`

Every table in `public` must have row level security enabled, because Supabase exposes
that schema through its public Data API. Migration `0001_lock_down_public_api` enables
it for existing tables and revokes the API roles' default privileges for new ones, and a
test fails if any table is missing RLS. New tables created by later migrations need
`ALTER TABLE ... ENABLE ROW LEVEL SECURITY` in the same migration.

## Deployment

Production: https://md-genius-launchpad.vercel.app

Vercel project `md-genius-launchpad` (team `mdgeniusai`) builds the client with
`npm run build:client` and deploys `api/index.ts` as the API function. Production
environment variables are set in Vercel; see `.env.example` for the full list.

- Supabase project: `md-genius-launchpad` (ref `klpwffswfhfwvsuqosct`, us-east-1).
- Runtime uses the transaction pooler (port 6543) with `DATABASE_SSL=require` and
  `DB_POOL_MAX=3`. Migrations use the session pooler (port 5432).
- Server-relative imports use `.js` extensions; Vercel runs the compiled files as native
  ES modules, which need them.
